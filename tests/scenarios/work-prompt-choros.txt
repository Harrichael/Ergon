## Ergon

These are ergon tasks; change them with the `ergon` CLI (`ergon help` lists
its commands, `ergon tree` shows each task's reference). As the work goes:

- Once all of a task's work is landed or in PRs, set it to landing:
  `ergon edit REF --status landing`.
- Until then, leave it in_progress, and set each subtask whose work is all
  landed or in PRs to landing.
- Name the task references (like demo/qxpj) in each PR's title or body.
- `ergon work` resumes this session only from the folder it began in, so
  don't move or archive that folder.

## Choros

This session's folder is in a choros space. `choros here` says:

```
here: workspace ws
```

`choros help agent` says how to work in it. Each `choros land` tells ergon
what it lands, so name the tasks a land carries with `--label`, by their
references (like `--label demo/qxpj`); with none named, it
carries the tasks of this session.

- `choros land continue` lands a piece. This workspace stays and the task
  stays in_progress. A subtask the land carries is set to landing for you,
  unless work under it is still open.
- `choros land archive` lands the last of the work: the task is set to
  landing for you and this workspace is archived. It is refused while a
  subtask is still todo or in_progress. `ergon work` then opens the set's
  landing folder, where review fixes go.

Don't run `choros archive` on this workspace.
